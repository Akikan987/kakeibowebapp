# 画面構成とナビゲーション

更新日: 2026-10-19。初めて開いたときの情報量を抑えるため、確認する情報と管理・編集を分ける。今回の対象は設定・割り勘・決済。収支・予算・履歴・追加画面の配置は変えない。

| 画面 | 初期表示 | 選んで開くページ |
|---|---|---|
| 設定 | プロフィールと同期状態の要約、5つの設定項目 | アカウント、表示テーマ、品目、連携・通知、データ管理 |
| 割り勘 | 未清算の「払う分」「受け取る分」と清算操作 | メンバー、共有の招待・承認、清算履歴 |
| 決済 | 次の引き落とし・7日／30日間の予定・プリペイド残高とチャージ | 引き落としカレンダー、カード・決済方法、口座・財布、チャージ履歴 |

## 操作の維持

- 設定一覧に編集フォーム・認証情報・Gmail本文や通知設定を常時展開しない。未同期は要約と上部の表示で分かるようにする。
- 設定のアカウント内にプロフィール・メール認証・外部ログイン・ログアウトを維持。アカウント削除は専用ページで、元の警告とパスワード・確認文字入力を保つ。
- 連携・通知には既存のメール／Android通知取り込み、Gmail接続・AI同意・通知登録・テスト通知を維持。項目を開くだけで権限を要求・変更しない。Gmail接続結果の「設定を確認」からは連携・通知へ直接進む。
- データ管理に端末保存状態・アプリ更新・CSV／JSON出力・JSON追加／全置換を集約。家計簿やログイン情報を削除する更新方式へは変更しない。
- 割り勘の0円になった相手もメンバーページで確認できる。初期画面に未承認の招待件数を表示する。メンバー追加だけでは共有せず、招待・承認・共有停止の説明と処理を維持。
- 決済方法の一覧行から既存編集画面へ進み、削除はその編集画面から行う。既定の現金／その他の削除禁止と使用中の削除制限は維持。
- カレンダーの日付選択・内訳・確定請求・支払状態、口座／振替、チャージの記録・取り消しを維持。予定額と確定額、手動残高と銀行実残高の区別は変えない。
- 決済トップの予定一覧は最初の3件だけを表示し、「さらに12件表示」から残りも確認できる。合計額の計算やカレンダーは全件を使い、表示件数で金額を減らさない。

## 戻る操作

`SectionNavigation`は画面内の経路を保持し、ブラウザー履歴をページごとに追加しない。Android／ブラウザーの戻ると、設定上部の戻るは最前面の共通ダイアログ、次に内部の親ページを優先し、一覧からは従来の収支画面／終了ガードへ戻る。画面内の戻るボタンも親ページへ進む。親へ戻る際に見出しをフォーカスし、画面上部から表示する。

今回の変更にDB移行・サーバーの計算変更・共有権限変更・追加のAI送信はない。表示確認は架空データで行い、実アカウントの設定や明細を変更しない。Android／iPhoneの実機固有の戻る・PWA表示は別途確認する。
