# 三井住友のメール・Android通知取り込み

更新日: 2026-10-14

## Gmail自動確認の追加

手動本文取り込みに加え、設定の「Gmailの利用通知を自動確認」から対象Googleアカウントを選択する機能を追加した。Googleログインとは別の読み取り許可が必要。初期対象は`smbc-debit@smbc-card.com`で、初回接続後の新着を約5分おきに解析し、暗号化された候補をサーバーへ保存する。本文は永続保存しない。本人が選んだ場合だけ、必須項目を読めても決済モードが不明な候補をOpenAIで補助判定する。必須項目の推測・自動保存はしない。

Web Pushは対応ブラウザー／PWAで明示許可後に利用し、通知には店名や金額を含めない。AndroidのWebView試験版へのPush追加ではない。Gmail専用OAuth・暗号鍵・通知鍵の設定が必要で、現時点は設定／本人許可待ち、実メール・実Pushは未検証。詳しくは[設定・データ取扱い・審査上の制約](https://github.com/Akikan987/kakeibo/blob/main/server/docs/GMAIL_IMPORT.md)を参照。

以下は先に公開した手動取り込みとAndroid通知の実装時点の記録。

## 今回できること

- Web/PWAの設定 →「メール・通知を取り込む」で、メール本文の貼り付け、UTF-8の`.txt`（128KB以下・本文32,000文字以内）を端末内で解析する。Gmailへのログイン・メール取得・メール転送用の受信サーバーは追加していない。`.eml`・HTML・画像の取り込みはこの機能の対象外。
- 提供されたOliveのデビット利用通知の書式に対応する。`利用日`／`利用日時`・`利用先`・`利用金額`のラベルと値を読み、日本時間で日時を解釈する。末尾の「利用日は日本標準時刻」「利用先は実際の店舗名と異なる場合」などの説明は項目と区別する。
- デビット／クレジットは取引項目より前の明示的なモード表示を優先する。注意書き中の「iDでは常にデビットモード」のみで支払モードを決めない。Oliveという名前だけでも決めない。
- `承認番号`はカード番号の末尾ではないため照合に使わない。明示的な末尾4桁とモードの一致が一意の場合だけ決済方法を候補にする。末尾がない今回の書式では本人が決済方法を選択する。Oliveのデビットはクレジットと別の決済方法として登録する。
- 読み取り結果 → 決済方法の確認 → 通常の支出入力画面 → 保存、の順。保存前に品目・金額・日時・割り勘などを変更できる。元メールの本文・承認番号は家計簿へ保存しない。保存する明細の取込元には取引項目のSHA256だけを付け、既存の同期形式・13テーブル・JSON v6を維持する。

## 誤記録・二重計上を避ける境界

- 利用通知は速報であり確定明細ではない。取消・返金・為替変更・手数料は後日公式明細で照合する。本文の手数料110円などを利用額へ勝手に足さない。
- 銀行の入出金、カード請求額、認証・利用不可・取消・返金のお知らせは通常の支出へ変換しない。ATM出金や口座引落をカード利用と二重に支出へ計上しない。
- メール本文は送信者の真正性を証明しない。今回はサンプルにある差出人アドレス`smbc-debit@smbc-card.com`に限り明示入力を受け付け、差出人を省略した場合は確認不能と案内する。他の書式・送信元はサンプル確認後に追加する。リンクを開く・HTMLを表示する・外部AIへ送る処理はない。
- 同じ取引項目の指紋が端末にある場合は再取り込みを止める。保存直前にも同一端末のDBトランザクション内で確認する。OCR／手入力との同日・同額・同決済の重複確認は通常の入力画面で行う。オフラインの別端末から同時に作った別ID同士の重複まで、サーバーで一意に禁止する機能ではない。

## Android試験版

`native/android`は、既存の公開Web画面を利用する小さなJava製Androidアプリ。旧Android専用クライアントの復活ではなく、WebのUI・計算・同期を共用する。Android 8.0（API26）以上、公開サイトへの接続と対応するAndroid System WebViewが必要。iOS版・ストア公開・OSウィジェットは今回追加していない。

1. 試験用APKを自分のAndroidにインストールする。端末へのインストール・権限設定を開発側から自動実行していない。
2. メール／ニックネーム等とパスワードでログインする。Chrome/PWAとはCookie・端末DBが別なので、未同期の記録があれば先にWeb版で同期する。既存アカウントの同期済みデータは同じサーバーから取得できる。
3. 設定 →「メール・通知を取り込む」で説明を確認し、収集を有効にする。Androidの通知アクセスは本人が許可する。権限画面に制限や警告が出た場合は無理に進めず、内容を確認する。
4. 三井住友銀行またはVpassで取引通知を有効にして、新たに通知が届いた後、「保留通知を読み込む」を押す。対象は`jp.co.smbc.direct`・`com.smbc_card.vpass`だけ。Gmail・SMS・他アプリ・過去のメールは読み取らない。
5. 通知を確認して入力画面へ進み、保存する。保存が成功してから、その保留通知だけを除外する。入力をやめた場合には保留を残す。不要な保留通知の個別除外、収集停止と保留全消去もできる。

通知本文が省略されていたり、メールと異なる項目名・日付形式だったりする場合は自動反映しない。実機の通知書式は確認待ちであり、採取できる全通知を支出へ変換できる保証はない。必要な項目が足りない場合は元の明細を見て手入力する。自動保存は行わない。

### 認証とプライバシー

- Google／LINEの認証は埋め込みWebViewとブラウザー間でCookieが共有されないため、試験版では新しい外部ログイン・連携を利用不可として案内する。Web/PWAの外部ログインは変更しない。既存連携の解除は通常の本人確認を維持する。
- 通知収集は初期OFF。ネイティブの説明画面で同意した後、OSの通知アクセス許可が必要。Androidが通知アクセスを広く許可しても、アプリ側では指定2パッケージだけを絞り込む。認証コード・パスワード・ログインなどの文言は保存対象から除くが、これはテキストによる最善努力のフィルター。
- 保留はアプリ専用領域にAndroid KeystoreのAES-GCMで暗号化。最大50件、読み取り可能なのは7日以内。期限切れの実データは次の収集・読み取り・状態確認時に掃除する。停止時は保留と暗号鍵を消す。通知本文をログに出さない。
- Webへの受け渡しは本人が「保留通知を読み込む」を押したとき。通常の保存・同期後は、確認した明細項目が既存の家計簿サーバーへ送られる。生の通知本文を同期するAPIはない。
- ブリッジは`https://app.kakeibodata.com`のトップフレームだけに許可し、送信元と現在の表示先を再確認する。`addJavascriptInterface`は使用しない。TLSエラーは停止、HTTP混在・ファイルアクセスは不可。信頼するWeb側にXSSが起きた場合まで、ブリッジだけで防げるわけではない。
- APKはデバッグ署名の個人確認用で、ストア公開版ではない。配布用の署名鍵は作成・公開していない。正式配布には署名管理・依存/対象SDK更新・ストア審査・実機テスト・プライバシー説明の整備が別途必要。
