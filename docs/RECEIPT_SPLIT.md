# レシートの商品別割り勘

2026-10-21追加。支払い直前の計算と、全額を立て替えた支出の人別負担への反映を補助する。送金・支払い実行機能ではない。

## 使い方

1. 「＋」→「支出を入力」→「商品を読んで割り勘」でレシート画像を選ぶ。通常のAI読み取りは従来の短い出力のままで、この操作だけ商品名・数量・行合計も要求する。同じレシートを通常読み取りした後に自動で再送することはない。
2. 合計などの候補を確認し、「候補を反映して商品を選ぶ」を押す。「一緒に会計するメンバー」を選び、商品ごとに頼んだ人を選ぶ。複数選択はその行を均等に分ける。「未割り当ての商品をすべて自分にする」は本人が押したときだけ実行する。
3. 数量がまとまった行は修正欄から2〜20点に分け、それぞれ別の人を選べる。金額は数量を含む行合計で、数量を二重に掛けない。商品名・数量・金額の訂正、明示的な値引きの負数、手入力の行追加／削除にも対応する。最大100行。
4. 商品合計と会計合計が違うときは反映を止める。税・値引き・欠けた行を確認して金額を修正するか、明示的に「確認済み：商品金額の比率で配分する」を選ぶ。混在税率や個人だけの割引等では一律の比例配分が正しいとは限らない。
5. 人別のお会計を確認し、必要なら「人別の割り勘金額に反映する」。既存の他の人の負担額を置き換えるだけで、保存は別操作。各自が店へ直接払う場合は計算の確認だけで使える。全額を本人が立て替えた場合に通常の支出として保存する。

メンバーの新規登録・編集は「割り勘」タブに集約したまま。メンバー名・選択・割り当てをAIへ送らない。外部AIを使わずに商品を手入力する計算も利用できる。

## 金額・安全性

- 印字された商品行合計を使い、合計・税の集計・預り金・釣銭等は商品に重ねて含めない。読み取り不明の価格は`null`で手入力待ちとし、数量や税をAIで補完しない。商品読み取りは出力が増えるため、通常より時間・API使用量が増える場合がある。
- 共有商品の1円未満の余りは参加者の表示順（本人が対象なら先頭）で配る。差額の比例配分は整数演算と最大剰余法を使い、同率の余りは表示順。負担がマイナス、未割り当て・不明価格・重複ID・削除されたメンバー・会計合計の不一致では反映しない。
- 金額計算は端末内。計算結果の人別合計が必ず会計合計に一致する場合だけ反映できる。通常の保存時にも既存の上限・負担総額・メンバー参照の検証を通す。
- 商品別の作業内容はアカウント別のローカル下書きにのみ保持し、再読み込み後は「下書きを復元する」から再開できる。画像・キー・トークンは保存しない。不正な商品下書きがあっても通常の入力下書きは維持する。
- **保存・同期・共有するのは既存形式の人別金額だけ**。商品別の割り当ては保存した明細・JSONバックアップ・別端末・共有相手には残らない。必要なら保存前に計算内容を確認する。DB移行・共有権限の変更はない。

## APIと制限

`POST /ocr/receipt`の`include_items=true`は、`mode=ai`・認証・既存AI送信同意がある場合だけ商品を要求する。省略・falseは従来の抽出項目と推論設定を維持。モデル・高精細画像・`store=false`・1回の呼び出し・日次上限・45秒通信／50秒全体上限・4,000出力トークン上限は変更しない。長いレシートで出力が完了しない場合は部分結果を採用せず、撮り直しや手入力を案内する。

商品は`items: [{name, quantity, line_total_yen}]`。各名前160文字、数量は1〜999またはnull、行合計は±20億円の整数またはnull、最大100件。名前の改行などは空白にまとめ、制御文字を拒否。古い応答・通常OCRは商品なしとして扱う。新しい項目付きリクエストは[OpenAIの構造化出力仕様](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)に従い、全項目必須・余分な項目を禁止する。構造への適合は、画像の認識や税の解釈の正しさを保証しない。

## 検証

計算・APIアダプター・下書き復元の自動テストに加え、架空データの390px幅で単独商品・共有商品・数量分割・差額配分・人別金額への反映・再読み込み後の復元を確認した。例：ラーメン900円（本人）、お茶300円（友人）、餃子600円（共有）、合計1,980円を明示的に比例配分し、本人1,320円／友人660円。横はみ出しなし。実際のレシート画像の認識精度・端末固有のカメラ/PWA動作は別途確認が必要。

2026-10-21の確認結果：

- API全258件、Web全168件の自動テスト、Webビルド、公開文書・PRページの検証が成功。
- 個人情報を含まない架空レシート1枚を実際のAIに送信し、3商品・合計1,980円・数量2の行合計600円を確認。1回の所要時間は3.71秒で、一般的な精度や処理時間を保証する値ではない。
- 390px幅の独立したローカル環境で保存まで確認し、友人への660円の請求と本人の支出統計1,320円が既存の仕様どおり反映された。
- 本番のAPI/Webを更新。公開HTML・新しい入力画面の配信・ヘルスチェック・Service Worker・プライバシーポリシーがHTTP 200、未認証の商品OCR要求が401であることを確認。
- 反映前に暗号化DBバックアップと旧イメージを確保。DB/OCRコンテナは再起動せず、本番の明細224件・割り勘21件・決済手段17件は反映前後で不変だった。実データのレシート送信や明細追加は行っていない。
