# デザイン方針と検証

更新日: 2026-10-27

## 取り入れた指針

[Emil KowalskiのSkills for Designers and Engineers](https://github.com/emilkowalski/skills)の `emil-design-eng`、`apple-design`、`mobile-native` を中心に適用した。`animation-performance` は動きのコスト確認、`break-ui` は現実的な長文・金額・空データの検証に利用。参照したmainは `2d228630ba1446365f614a108cb8252f1feda202`。5件のスキルは開発者のCodexユーザーフォルダーへ導入し、アプリの配信物には含めない。

見た目の全面的な入れ替えではなく、既存のMUI、画面構成、ライト／ダークの選択を維持する。操作や金額を隠して簡素に見せるのではなく、階層・余白・応答で迷いを減らす。

| Before | After | Why |
| --- | --- | --- |
| コントロールの押した反応が不統一 | ポインター押下だけに120msの控えめな縮小 | 入力への即時フィードバック。キーボード・無効状態では縮小しない |
| 通常カードにも半透明・グラデーション | 本文は不透明、ガラスは主にナビゲーション | 透過面の重なりと低コントラストを避ける |
| 月変更で棒グラフの高さが変化 | 金額グラフは即時切り替え | 毎日の操作を演出で待たせず、レイアウトのアニメーションを避ける |
| 画面幅にかかわらず収入・支出が2列 | カード内幅が17rem未満なら1列、長い金額は24remまで1列 | 大きな金額を省略せず、通常の金額では日付別支出を上に保つ |
| 件数バッジが長い名前を圧迫 | バッジを本文側の補助情報として配置 | 矢印・アイコンの領域を保ち、名前を読めるようにする |
| モーダルを閉じる操作が背景・戻る頼み | 見える閉じるボタンと名前付きダイアログ | 操作の出口を明確にする。既存の戻る順序は維持 |
| 長いモーダル名が本文を押し出す | 見出しは最大40dvhで独立スクロール | 文字200%でも入力・閉じる操作に到達できる |
| maximum-scale=1 | 拡大制限を削除 | ピンチズームを妨げず、入力欄を16px以上にする |

## 継続するルール

- ボタン48px以上、アイコン44px以上。本文・エラー・金額はコピー可能で、文字選択を禁止するのは操作部分だけ。
- 押下演出はtransformのみ。ページ全体・金額・グラフの登場演出、毎フレームのReact状態更新、新しいアニメーションライブラリは追加しない。
- `prefers-reduced-motion` ではポータルを含めてアニメーション・遷移を停止。透明度を抑える設定・高コントラスト・強制配色では不透明な表示へ戻す。
- キーボードのフォーカス輪郭を残す。タップでhover色が残り続けないよう入力デバイスの機能で分岐する。
- Android向けの単一 `meta#theme-color` と動的な色更新、マニフェストのダーク初期値は維持する。設定に連動しないmetaを追加しない。
- セーフエリアとソフトキーボードに配慮する。`viewport-fit=cover`・`interactive-widget=resizes-content` と既存の上部／下部余白を維持する。
- 下部ナビゲーションの高さ・本文の下余白・通知の位置はremで文字サイズに追従させる。通常サイズの位置関係は維持する。
- 金額計算、保存・同期、割り勘権限、OCR/Gmail送信や同意は変更しない。

## 開発用の表示崩れチェック

`npm run dev -- --host 127.0.0.1` で起動し、`/?design-preview=1` を開く。`Demo data / Worst case / Empty / One / 1,000 rows` の切り替えはURLの `data` に保持する。文字200%・テーマ切り替え・入力ダイアログのボタンも利用できる。

本番と同じ `MonthlySummary`・`NavigationRow`・共通入力／ダイアログを、propsの境界に架空データを渡して描画する。アカウントストア・API・AI・Service Workerを起動せず、家計簿への保存や外部送信をしない。`import.meta.env.DEV` の条件で本番ビルドから除外する。

| 対象 | 入力元・制限 | 検証内容 |
| --- | --- | --- |
| カード名／見出し | NavigationRow.title、APIのカード名は100文字まで | 長い家族カード名・短いJo・絵文字・ベトナム語 |
| 説明 | NavigationRow.description、共通部品としては上限なし／省略可能 | 長いexample.comのメール・説明なし |
| 件数・状態 | NavigationRow.badge、省略可能 | 0・1・1,284件・注意 |
| サマリー金額 | MonthlySummaryの集計結果、個別金額上限を超える月合計もあり得る | 0・負数・10桁の円表示。省略・切り捨てなし |
| 一覧 | NavigationRowの配列 | 0・1・4・1,000行。大量データはこの検証画面のみ固定高スクロール |
| 入力・閉じる操作 | 共通Field/Modal | 金額入力、電卓、長いタイトル、無効ボタン、閉じるボタン |

RTLの製品対応は今回追加しない。1,000行の検証は実機のスクロール性能保証ではなく、本番の履歴ページング方式も変更しない。

## 確認記録

- Web全175件のテスト成功（今回追加7件）。型検査・本番ビルド・公開文書・PRページの検査を実施。通常画面の決済方法ダイアログでMUIの自動見出しIDとの重複も解消した。
- 320px幅・文字200%の架空データで、金額の省略／横はみ出しがなく、長いタイトルでもモーダル本文と閉じる操作を利用できることをブラウザーで確認。
- 390pxのライト／ダーク、1024pxの横幅、空・1件・1,000件の検証データでも横はみ出しなし。実際の保存や外部AIは呼ばずに確認した。
- 検証画面が本番のチャンクに含まれないことを確認。
- 2026-10-27 01:26 JST、ダイアログ修正を含む最終版を本番Webのみ反映。公開トップの `index-BA7nyqx3.js` と新しい収支／ナビゲーション／CSS、Service Worker、`/health`、紹介ページのHTTP 200を確認。公開HTMLに拡大制限がなく、配信JS・イメージ内に開発用プレビューが含まれないことも確認した。
- 復旧用イメージ `kakeibowebapp-web:before-emil-design-20261027` と再作成前の暗号化ログを保持。API・DB・OCRの起動時刻は変わらず、実ユーザーの明細を追加・変更していない。
- 実機Android/iPhoneのキーボード・タップ感・PWAセーフエリア、実機でのフレーム時間は未検証。エミュレーションだけで実機の問題が解決したとは扱わない。

### 別件の依存監査

今回のDockerビルド時の `npm audit` は3件（vite: 高、fast-uri: 中、serialize-javascript: 低）を検出した。既存の依存ツリーに対する警告で、今回の変更ではpackage.json／package-lock.jsonやライブラリを追加・更新していない。開発サーバー／ビルド環境の更新が別途必要。本番の配信イメージはNginxと静的成果物のみでNode/Viteの開発サーバーは起動しないが、このことは依存全体の安全性を保証しない。検証用開発サーバーは作業終了時に停止する。
