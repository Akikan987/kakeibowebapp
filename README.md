# 家計簿 Webアプリ

ドキュメント更新日: 2026-09-27

## 最新の実装状況

- 最新の機能実装: Web [`2f30aaa`](https://github.com/Akikan987/kakeibowebapp/commit/2f30aaa)、API [`4bdc3a8`](https://github.com/Akikan987/kakeibo/commit/4bdc3a8)。2026-09-25に本番反映・両リポジトリへのpushを確認済み。
- 金額欄の電卓、手動の口座・財布残高、口座間振替、元の支出に対する返金、新規の割り勘共有の招待・承認まで実装済み。移行前の共有は維持する方針。
- 端末DBはDexie version4、同期対象は13テーブル、JSONバックアップはversion6。共有権限はサーバーだけで管理する。
- 直近の検証結果はWeb58件／API43件の成功、型検査・本番ビルド・公開配信確認。これは2026-09-25の反映時の記録であり、今回の文書更新でテストや本番反映を再実行したものではない。

ブラウザだけで使える家計簿アプリ。収入・支出の記録、品目別／日付別グラフ、割り勘の管理、レシートの読み取りができる。

**公開URL: https://app.kakeibodata.com** — 誰でもアクセスでき、アカウント登録もその場でできる。

**紹介ページ: https://app.kakeibodata.com/pr/** — アプリの主な機能を紹介する独立したPRページ。

> これが家計簿の**メインアプリ**。Android版は2026-08-31に廃止済みで、[kakeibo](https://github.com/Akikan987/kakeibo)は現在サーバー専用リポジトリ。Android・iPhoneともWeb/PWA版を利用する。

## できること

| 機能 | 内容 |

| 入力補助・下書き | 同じタイトルの履歴から品目・決済方法を候補表示。同日・同額の重複確認、端末内の下書き復元、保存直後の取り消しに対応 |
| 決済方法 | プリペイド／クレジット／デビット／現金／その他を登録し、支出ごとに指定。カード名から公式確認済み候補を補助検索 |
| カード引き落とし予定 | 次の引き落とし・今日を含む7日／30日間の合計を、確定額と見込み額に分けて表示。カード別に利用・チャージの内訳を確認 |
| 引き落としカレンダー | 月間カレンダーに日ごとの引き落とし合計を表示。日付を選ぶとカード別の金額を確認 |
| プリペイド残高 | チャージ元も記録し、チャージ額から実際の利用額を差し引いて残高を表示 |
| グラフ | 月ごとの収入／支出／収支、日付別の棒グラフ、品目別の円グラフ。各グラフをタップすると金額を表示 |
| 品目 | 自由に追加・改名・削除・並び替え（ドラッグまたは↑↓） |
| 割り勘 | 支出のうち「他の人の負担」を人ごとに指定。本人を含む人数で均等割りを自動入力でき、統計には**自分の負担ぶんだけ**反映される |
| 割り勘の相手連携 | 割り勘タブから招待し、相手の承認後に「払う分」を共有。移行前の既存共有は維持する。双方から共有停止可能 |
| 口座・財布（手動） | 開始残高と入出金を記録し、口座ごとの参考残高と今後30日のカード予定額を表示。銀行接続は行わない |
| 振替・返金 | 口座間振替は収支に含めず、元の支出にひも付けた返金は返金月の支出を減額 |
| 金額電卓 | 金額欄の横から四則演算・括弧・小数の計算。端数処理を確認してから金額へ反映 |
| 清算 | 受け取った額を記録すると残額が減る |
| レシート読み取り | OpenAIが題名・合計金額・日付・品目・決済方法の候補を解析し、確認後に入力欄へ反映。通常OCRと手入力も利用可能 |
| 表示テーマ | 端末に合わせる／ライト／ダークを選択。PWAのステータスバー色にも反映 |
| プロフィール画像 | 画像を正方形に縮小してアカウントへ保存し、ログイン端末間で共有 |
| プロフィール編集 | 右上の設定から名前・画像を変更。メール変更は新しいアドレスに届く6桁コードで認証して確定 |
| アカウント削除 | 現在のパスワードと確認文字を要求し、アカウントとサーバー／端末上の全データを完全削除 |
| データ出力・バックアップ | 明細をCSVへ出力。全データはJSONファイルに書き出し／取り込み |
| 履歴検索・複製 | 月送りで対象月を切り替え、店名・品目・決済方法や期間・金額などで絞り込み、過去の明細を現在日時で複製 |
| 定期項目 | 家賃・給与などをテンプレート保存し、対象月を確認してからワンタップで明細登録。端末間の二重登録を防止 |
| 月間予算 | 全体予算と品目別予算を月ごとに設定し、使用額・残額・進捗を予算タブで確認 |
| カード請求照合 | 計算上の引き落とし予定をカード会社の確定額で上書きし、確定／引き落とし済みを管理 |

## 決済と集計の考え方

- クレジットカードの利用は、利用日が締め日以前なら翌月、締め日後なら翌々月の引き落とし予定に集計する。`31日` は月末として扱う
- プリペイドへのチャージは家計簿の支出統計に入れず、プリペイドで実際に使った金額だけを統計へ反映する
- クレジットカードからプリペイドへチャージした場合、チャージ額はそのカードの引き落とし予定へ加算する
- 初期残高や現物で受け取った残高は「初期残高・残高調整」として登録でき、他の決済方法へは加算しない
- 休日による引き落とし日の前後調整はカード会社ごとに異なるため行わない

### 支払い予定の見方（2026-09-24追加）

- 決済タブの先頭に「次の引き落とし」と、今日から6日後／29日後までの合計を表示。同日に複数カードがある場合は合算する。
- カード会社の請求額を入力したものは「確定」、利用履歴から計算したものは「見込み」。支払済みは今後の合計から除外し、カレンダーには残す。
- 過去の予定は「支払確認待ち」として折りたたむ。アプリ上で未確認という意味で、実際の未払い・延滞を判定する機能ではない。
- カードの行を押すと、その請求に対応するカード利用・プリペイドチャージを表示する。割り勘相手の負担も含めたカード決済の全額で、家計簿の本人負担額とは異なる。
- 対応する利用履歴がなくなっても、保存した確定請求額・支払状態は表示を維持する。確定額との相違や休日調整はカード会社の明細で確認する。

### 入力補助・下書き・取り消し（2026-09-24追加）

- 新規入力で同じタイトルの過去の記録があると、使用頻度順に最大3件の品目・決済方法候補を表示。ボタンを押したときだけ反映し、手入力はそのまま使える。
- 同日・同額・同じ種類（支出は同じ決済方法）の記録があれば保存前に確認する。タイトルが違っても候補になり、別の買い物なら確認して保存できる。自動統合・削除はしない。
- 入力途中のタイトル・金額・日時・品目・決済方法・割り勘は、アカウントと編集対象ごとに端末のlocalStorageへ保存する。＋ボタン、または同じ明細の編集を開き直し「下書きを復元する」を押す。新規下書きはアカウントごとに1件で、復元せず入力すると上書きする。
- レシート画像は下書きに保存せず、下書き自体も別端末やサーバーへ同期しない。編集対象が更新されていたら古い下書きは復元しない。保存完了、ログアウト、アカウント削除で対象の下書きを消す。サイトデータ削除・保存領域不足には復元を保証できない。
- 保存後の通知で約10秒間「取り消す」を表示。新規保存は論理削除、編集は保存前の内容へ戻し、割り勘も同じトランザクションで反映する。その後に別の編集や同期による変更があった場合は取り消さず、履歴での確認を促す。
- この入力補助の導入時点では口座・振替・返金・招待承認は対象外だったが、下記の追加実装で対応。銀行API接続は未実装。

### 口座・財布・振替・返金・承認共有・電卓（2026-09-24追加）

2026-09-25にAPI・管理画面・Webへ本番反映。Web58件／API43件のテスト、ビルド、公開サイトの配信内容を確認済み。詳細は[検証記録](docs/ARCHITECTURE.md)を参照。

- 「決済」→「口座・財布」で名前・開始残高・開始日時を登録する。開始日時直前の残高を基準に、それ以降かつ現在までの記録から計算する。銀行口座番号・認証情報は不要で、実際の銀行残高を取得する機能ではない。
- 現金・デビット等の決済方法に既定の口座を設定すると、以後の支出の初期値になる。収入は入力画面で入金先を選ぶ。過去の記録は自動で口座に結び直さず、履歴で個別に編集する。定期支出は登録時の決済方法の既定口座を使用し、定期収入の口座は登録後に編集する。
- カード利用時には口座残高を減らさず、「引き落とし済み」の請求に保存した口座・実際の支払日時・確定額で減らす。口座未指定なら残高に含めない。既定口座の変更は、過去に保存した入出金・請求の口座を移動しない。
- 「口座間の振替」は手元の資金移動の記録だけ。収支統計や合計資産を増やさず、銀行送金は実行しない。手数料・割り勘の実際の受け渡しは自動反映しないため別途管理が必要。
- 履歴の返金ボタンから、本人負担分の返金額・日時・返金先を登録する。返金月の支出を減らし、収入には含めない。累計額は元の本人負担額まで。割り勘相手の負担や清算額は自動変更しない。相手分を含む返品は、負担配分を見直してから入力する。
- 現金等の返金は指定口座へ加算、プリペイド返金は残高へ加算。カード返金は明細で確認した請求日を指定して見込み額から控除する。確定済み請求は自動変更せず、返金超過によるマイナス請求は0円止め（翌月への繰越・銀行振込は自動計算しない）。
- 招待は割り勘タブから相手のアカウント名を指定して送る。承認されるまでは共有しない。承認後はそのメンバーに割り当てた過去・今後の合計額と清算状況だけを相手へ表示し、明細全体・口座残高は共有しない。移行前の共有は「既存共有」として維持する。共有停止後も明細・清算記録は残る。辞退・停止後の同じメンバーへの再招待は24時間後から。
- 名前の変更・JSON復元・古いアプリからの同期では共有権限を作れない。招待・承認・停止はログインと通信が必要。オフライン端末の古い表示は次回同期まで残る。
- 金額欄の電卓は四則演算・括弧・小数に対応する。演算途中は分数として正確に保持し、1円未満は最後に四捨五入／切り下げ／切り上げを選択。反映ボタンを押すまで入力値を変えず、キャンセルで元の値を維持する。API通信・外部サービス料金は発生しない。
- JSONバックアップをバージョン6に拡張し、口座・振替・返金・支払口座の記録も含める。共有の許可はサーバー管理で、JSONから復元しない。口座データがある端末では旧バックアップによる全置換を拒否する。CSVには返金の減額行と収支対象外の振替行を区別して出力する。
- 同期は13テーブルに拡張。APIを先に更新してからWebを更新する。口座等の記録がある場合、非対応の旧サーバーへの送信を「同期成功」とは扱わない。端末のデータ削除・再ログインは不要。

## 特徴

- **インストール不要** — URLを開くだけで使える
- **アカウントなしでも使える** — 後から登録すれば、それまでのデータもそのまま同期される
- **オフラインで動く** — 記録は端末内（IndexedDB）に保存され、オンライン時にサーバーと同期
- **未同期を見失わない** — 通信失敗時は画面に表示し、オンライン復帰時と未同期中に自動で再試行
- **サーバーが止まっていても起動できる** — Service Workerがアプリ本体を端末に保存している
- **必要な画面だけ読み込む** — 画面単位のコード分割により、最初に解析するJavaScriptを軽量化
- **ホーム画面に追加**すればアプリのように全画面で起動（PWA）

## 構成

```
ブラウザ (React SPA + IndexedDB)
      │  同一オリジン
      ▼
Cloudflare Tunnel ── app.kakeibodata.com
      ▼
nginx (kakeibo-web)  … 静的配信 + API中継
      ▼
FastAPI (kakeibo-api) ── PostgreSQL (kakeibo-db)
      ├─────────────── YomiToku (kakeibo-ocr)
      └─────────────── OpenAI（明示的な同意時のみ）
```

サーバー側は [kakeibo](https://github.com/Akikan987/kakeibo) リポジトリの `server/` にある。

ソースの責務分担・最適化の測定結果・今後の整理方針は [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) を参照。

- **React + TypeScript + Vite** / Material UI（Material Design 3風テーマ）
- **Dexie（IndexedDB）** でローカル保存
- **vite-plugin-pwa** でService Worker生成
- **nginx** が静的配信とAPI中継を兼ねるので、CORSが不要

## 同期のしくみ

既存レコードの後方互換を維持しつつ、口座・返金・共有承認は対応する新APIを必要とする。

- 各レコードは **UUID主キー + `updated_at` + `deleted`（論理削除）**
- 競合は**最終更新優先（last-write-wins）**でマージ
- `POST /sync` で「自分の変更を送る」と「サーバーの変更を受け取る」を同時に行う
- **毎回全件を照合**し、端末が既に持つ同一内容の返信だけを省く（`since: 0` / `omit_unchanged: true`）。時刻ベースの差分同期は取りこぼしの原因になったため使わない。省略フラグは旧APIでも扱えるが、口座・振替・返金の記録がある場合は3つの新テーブルを返さないAPIへの同期をエラーにし、端末データを保持する
- `members.linked_uid` はサーバー管理。新規共有は招待の承認後に有効になり、名前の一致・JSON復元だけでは共有を開始しない
- 端末DBの同一行は書き直さず、変更行をトランザクションで反映する
- 同じ名前の品目が複数できた場合は自動で1つにまとめる（残す1件はID最小で決めるので、どの端末でも同じ結果に収束する）

## データの保存先と持続性

- 記録は端末内の **IndexedDB**（DB名 `kakeibo`）に保存。ブラウザを閉じても端末を再起動しても残る
- 起動時に `navigator.storage.persist()` を要求し、ブラウザの自動削除を受けにくくする
- **ホーム画面への追加を推奨**。特に iOS Safari は、未インストールのサイトの保存領域を**7日間の未訪問で削除**する
- 「閲覧データを削除」やプライベートモードでは消える。大事なデータはログインしてサーバーに同期しておく

## 開発

```bash
npm install
npm run dev     # http://localhost:5173（APIは localhost:8000 へプロキシ）
npm test        # 決済・集計・レシート照合・同期とIndexedDBの回帰テスト
npm run build   # dist/ に出力
```

家計簿サーバー（`kakeibo` リポジトリの `server/`）が `:8000` で動いている必要がある。

アイコンを作り直すとき:
```bash
node scripts/gen-icons.mjs   # public/icon.svg から PNG 各サイズを生成
```

## デプロイ

```bash
docker compose up -d --build   # http://localhost:3000
```

Cloudflare Tunnel の Public Hostname（`app` → `kakeibodata.com` → `HTTP localhost:3000`）で公開している。
API（`kakeibodata.com`）は別リポジトリで運用する。両方を変更するときはAPIを先に反映し、次にWebを更新する。

## 2026-08-29〜30 変更まとめ

- **決済管理** — プリペイド／クレジット／デビット／現金／その他を登録でき、カードの締め日・引き落とし日・予定額とプリペイド残高を確認できるようにした
- **プリペイドの実態に沿った集計** — チャージ額は支出統計へ直接入れず、実際に使った額だけを家計簿へ反映。カードからのチャージはそのカードの引き落とし予定へ加算する
- **カード入力の補助** — 公式情報を確認したカードプリセットを用意し、カード名から締め日・引き落とし日の候補を展開表示して反映できるようにした
- **引き落としカレンダー** — 日ごとの引き落とし合計をカレンダーに表示し、日付タップでカード別の予定額を確認できるようにした
- **履歴検索・複製** — キーワード、種類、品目、決済方法、期間、金額、割り勘有無で絞り込み、過去の明細を複製できるようにした
- **定期項目** — 家賃・給与などを保存し、対象月ごとに内容を確認してから登録できるようにした。同じ月への二重登録は端末間でも防止する
- **予算管理** — 月ごとの全体予算・品目別予算と、使用額・残額・進捗をホームに表示するようにした
- **カード請求の照合** — 計算上の予定額とカード会社の確定請求額との差額を確認し、請求確定／引き落とし済みを記録できるようにした
- **Material UI化** — 画面をMaterial UIで再構築し、端末連動／ライト／ダークのテーマ切替とPWAステータスバー色の連動を追加した
- **プロフィール編集** — プロフィール画像とニックネームを変更可能にし、メールアドレスは現在のパスワード確認と新メール宛6桁コードの認証後に変更する方式にした
- **割り勘共有** — メンバー管理を割り勘タブへ集約し、登録ユーザーとの連携状態、相手が払う分、自分が払う分、清算履歴を確認できるようにした
- **ナビゲーション整理** — 下部ナビを収支／予算／履歴／決済／割り勘の5タブにし、設定は各画面右上のアイコンから開く形へ変更。最後に開いたタブと明細追加元を保持する
- **安定性・安全性** — 未同期データの自動再送、トークン有効期限、認証系レート制限、OCRとプロフィール画像のサイズ制限、PostgreSQLの定期バックアップを追加した
- **PRページ** — `/pr/` に独立した紹介ページとSNS共有画像を追加。容量の大きいPR画像はアプリ本体のPWA事前キャッシュから除外した

### AIレシート読み取り（2026-09-23追加）

- 支出入力の「レシートから入力」で、OpenAIへの画像・登録済み品目名の送信に同意して読み取る。外部AIを使わない通常OCRも選べる（いずれもサーバーへ画像を送信）。
- 候補の確認画面を経て題名・金額・日付・品目・決済方法を反映する。読み取りだけでは保存されず、反映後も修正・手入力できる。不明な項目は元の入力値を維持するので保存前に確認する。
- 「決済」の登録・編集でカード末尾4桁を任意に登録できる。番号全体は入力しない。末尾は文字列で保存し、先頭の0、同期、JSON出力・取り込みに対応する。
- レシートの末尾と登録済みカードが一意に一致した場合だけ候補を選ぶ。重複・不明・併用・不確実な場合は手動選択。モバイル決済ではカード券面と末尾が異なることがある。現金や電子マネー名も一意に判断できる場合だけ選ぶ。
- サーバーの `server/.env` に `OPENAI_API_KEY` を設定してAPIコンテナを再作成すると有効になる。ブラウザ側やGitにはキーを置かない。未設定でも通常OCR・手入力は利用可能。
- モデルはサーバーの `RECEIPT_AI_MODEL` で変更可能（既定 `gpt-5-mini`）。API利用料が発生する。アプリ側では画像を永続保存せず、OpenAIへは `store=false` でリクエストするが、提供元側のデータ保持ゼロを保証するものではない。
- 1ユーザー30回／全体300回の24時間上限が既定。APIプロセスの再起動でリセットされる簡易制限で、厳密な課金上限ではない。設定手順・制約はバックエンドの `server/README.md` を参照。
- 2026-09-23、本番APIコンテナの解析関数からOpenAIへ合成レシート1枚を送信し、店名・合計1,188円・日付・品目「食品」・カード末尾「0123」・カード決済・確実度の7項目が期待値と一致した（約7秒）。本番の家計簿データは登録・変更していない。照合・応答検証・エラー制御の自動テストに加えた接続確認であり、実際に撮影したレシート全般の精度や画面操作全体を保証するものではない。
